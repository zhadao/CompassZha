# 架构说明

本文档面向想读懂或修改本项目的开发者，说明代码分层、数据流向与几条不可违背的工程红线。

## 一、总体分层

```
┌───────────────────────────────────────────────┐
│  components/          Svelte 5 组件（纯展示 + 交互）      │
│  只调用 store 方法，不碰文件 API、不碰 invoke          │
├───────────────────────────────────────────────┤
│  stores/app.svelte.ts 全局状态单例（AppState）           │
│  内存态数据 + 脏标记 + 防抖落盘调度 + 派生数据           │
├───────────────────────────────────────────────┤
│  lib/                                           │
│   markdown.ts   Markdown 解析 / 章节级写回            │
│   tauri-fs.ts   唯一允许 invoke 的地方（路径安全层）      │
│   date.ts       日期工具                            │
├───────────────────────────────────────────────┤
│  src-tauri/           Rust 后端（Tauri 2）              │
│   fs_cmds.rs    异步文件系统命令 + 路径校验 + 后台 git     │
└───────────────────────────────────────────────┘
```

**单一接缝原则**：组件永远只跟 `stores/app.svelte.ts` 打交道。这样数据源可以从「内存 mock」
平滑切到「真实文件系统」，而不改动任何组件——项目在原型阶段就是靠这条接缝完成换血的。

## 二、数据流

### 读路径（启动一次 + 按需）

1. `App.svelte` 挂载时调用 `app.loadAll()`。
2. `loadAll()` 扫描 `daily/` 全量年份目录与 `life/` 一级子目录，把每个文件解析进内存：
   - `daily/yyyy/yyyy-mm-dd.md` → `DailyNote`（指标、清单、记录、收尾）+
     `FocusSession[]`（由 `## 专注记录` 派生）+ `EventItem[]`（由 `## 日程` 派生）
   - `star-` 前缀的文件名 → 收藏日期集合 `starredDates`
   - `life/<板块>/<文件>.md` → `LifeBoard { files: BoardFile[] }`
3. 若当天文件不存在，按模板创建（**已存在则绝不覆盖**）。

> 当前数据量级（每天一个文件）用**文件扫描 + 内存索引**已足够，因此没有引入数据库。
> `docs/ROADMAP.md` 中列为可选优化的「SQLite 派生索引」是可随时整库重建的加速层，
> 不承担数据权威性。

### 写路径（核心设计）

UI 上的任何修改都走同一条流水线：

```
用户操作
  └─ 组件调用 store 方法（如 toggleTask / setMetric / logFocusSession）
       ├─ ① 更新内存态（$state），界面立即响应
       └─ ② markDirty(date, aspect)   ← 只标记「哪个日期的哪个章节脏了」
              └─ 500ms 防抖合并
                   └─ flush()
                        ├─ 读磁盘现文（作为基底）
                        ├─ 只对脏章节做「手术式替换」（lib/markdown.ts）
                        ├─ 写回文件
                        └─ 本地 git add + commit
```

关键点：

- **去抖合并**：连续输入不会造成 N 次磁盘写与 N 次 git 提交。
- **以磁盘现文为基底**：不信任内存副本，避免覆盖用户在外部编辑器里做的改动。
- **章节级手术**：只替换被修改的章节，其它章节与 frontmatter 中的未知字段**字节级保留**。

## 三、章节级写回契约

每日文件被划分为若干「章节」（`## XX` 二级标题）。写回函数（`writeTasks` / `writeNotes` /
`writeReview` / `writeFocusLog` / `writeSchedules` / `writeMetrics`）遵循同一约定：

1. 用容错正则定位章节（允许 `##日程` 无空格、全角空格、CRLF、`- [X]` 等手写变体）。
2. 只替换该章节的正文区间，章节外的所有字节原样保留。
3. 无法识别的章节与行**原样不动**——宁可留着看不懂的内容，也不做规范化重排。

这条契约是整个项目的根基：**Markdown 文件是用户的财产，应用只是它的编辑器之一。**

## 四、安全与路径校验

前端只能向 Rust 传递**相对数据根目录**的路径；Rust 侧统一校验：

- 拒绝绝对路径、盘符、`..` 上跳、以及规范化后逃出数据根目录的路径。
- 所有命令是显式注册的白名单命令，前端无法调用任意系统 API。

## 五、性能红线

这些规则是被真实故障教训换来的（窗口卡死、黑窗闪烁），改动前请先读原因：

| 规则 | 原因 |
| --- | --- |
| Tauri command 一律 `#[tauri::command(async)]` | 同步命令在主线程执行，会冻结窗口 |
| git 子进程放在后台线程，并带 `CREATE_NO_WINDOW` | 每次保存要起多个 git 子进程，同步执行会「未响应」；不带标志会在窗口上方闪黑框 |
| 组件建议 ≤ 300 行 | 过大的单文件组件难以维护，按职责拆分 |
| 设计变量集中在 `tokens.css` | 避免色值散落各处，保证主题一致 |
| 不引入重型/含 `require('fs')` 的解析库 | 某些 CJS 包在 WebView 中模块加载阶段即崩溃，故 frontmatter 使用自带轻量实现 |

## 六、状态管理约定（Svelte 5 runes）

- 全局状态是**单例**（`AppState` 类实例），生命周期与应用一致。
- **惰性创建与纯读必须分离**：`getNote(date)` 会按需创建当日数据（含副作用），
  而组件在 `$derived` 中读取时必须调用纯读版本 `peekNote(date)`——
  在派生表达式里触发状态写入会报 `state_unsafe_mutation`。
- 派生值一律用 `$derived`，不要在模板里做重计算。

## 七、技术选型理由

| 选择 | 理由 |
| --- | --- |
| Tauri 而非 Electron | 复用系统 WebView，安装包与内存占用都低一个数量级 |
| Svelte 5 runes | 无虚拟 DOM，状态与视图同构，代码量小 |
| 纯 Markdown + 本地 git | 数据可读、可 diff、可被 AI 与脚本直接消费，无锁定 |
| FullCalendar / ECharts / Milkdown | 均为成熟 MIT 项目，直接复用其交互与渲染，自身只写业务胶水 |

## 八、已知取舍与待办

- **数据目录默认值**：默认取 `%USERPROFILE%\CompassZha`（当前用户主目录下的 `CompassZha`）。换目录可通过
  `config.json` 的 `data_root` 覆盖。
- **SQLite 派生索引**：尚未实施。阶段四的语料检索采用本地关键词打分（轻量 RAG 路线），
  当前规模下文件扫描足够；FTS5 / 向量索引保留为后续可升级路线。
- **日历拖拽的自动化测试**：FullCalendar 的 `dateClick` 需要真实指针事件，
  合成事件无法触发，因此该交互只能人工验证。
